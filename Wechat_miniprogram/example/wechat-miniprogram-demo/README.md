# BCL 戒指微信小程序 Demo

本示例用于在微信开发者工具和真机上验证微信小程序适配层。

当前页面包含：

- 蓝牙设备搜索
- 设备选择与连接
- 断开连接
- 时间同步
- 读取时间
- 获取硬件版本
- 获取固件版本
- 获取电量信息
- 获取充电状态

## 使用方式

1. 使用微信开发者工具打开本目录。
2. 直接点击“编译”。
3. 使用真机预览或真机调试，打开蓝牙权限。
4. 点击“蓝牙设备搜索”，选择设备后连接并调用指令。

蓝牙指令必须连接真实戒指设备后才能验证响应。开发者工具只能辅助检查页面和基础调用流程。

当前 Demo 页面使用原生 `.js` 文件，并通过 `libs/bcl-ring-sdk.js` 加载本地 SDK 包。这样可以避开微信开发者工具的 TypeScript 编译链路和 npm 构建链路。

然后重新打开微信开发者工具并点击“编译”。

## App 登录 Token

微信 adapter 提供 `createWechatTokenStore`、`setWechatToken` 和 `clearWechatToken`。登录由小程序业务层完成时，可以把已有 Token 写入微信本地存储，网络 SDK 会在后续请求中自动读取：

```js
const tokenStore = createWechatTokenStore({ wx })
const networkSDK = new BCLRingNetworkSDK({ fetch: wechatFetch, tokenStore })

setWechatToken({ wx }, loginResult.token)
clearWechatToken({ wx })
```

## Apollo 固件升级示例

首页“固件升级 · Apollo”提供两个入口，都会打开独立升级页，复用同一个 SDK 升级流程。固件准备可以在未连接时完成；开始升级前必须连接与固件匹配的 Apollo 戒指。

### 历史版本下载升级

1. 在首页配置网络区域和所需登录 Token，然后进入“历史固件下载升级”。
2. 输入固件分类并点击“查询历史版本”。默认 `Z5X` 对应本项目测试文件系列；其他设备需填写自己的分类，不能仅根据 OTA 类型猜测分类。
3. 在完整历史列表中选择指定文件，点击“下载所选固件”。不会自动下载第一项，也不会把 filePath 当作 URL。
4. 下载成功后读取二进制并校验 Apollo 文件头/正文长度，核对页面展示的文件名、大小及设备型号。
5. 点击“开始 Apollo 升级”，观察独立的传输阶段和设备确认进度。

服务端列表项需包含 `fileName` 和 HTTPS `fileUrl`，非 bin 或缺少地址的条目不可选；空列表和接口错误会明确显示。下载器会创建 `${wx.env.USER_DATA_PATH}/firmware` 目录，清理同名旧文件后保存，并在失败时停止流程。需要在小程序后台配置 API 的 request 合法域名和实际固件地址的 downloadFile 合法域名；重定向地址也应按微信要求配置。

### 微信聊天文件升级

1. 将 `.bin` 文件发到文件传输助手或微信聊天；
2. 进入“聊天文件升级”，点击“从聊天记录选择 bin 文件”。
3. 选择后立即按 ArrayBuffer 读取并校验；取消选择不会报告错误，也不会继续使用上一次文件。
4. 核对文件和设备后点击“开始 Apollo 升级”。

切换来源、重新查询或选择其他历史版本，都会清除已准备文件，避免意外使用旧文件。

### 升级状态、取消与日志

- 固定使用 237 字节有效负载，当前连接需确认 MTU 至少 240；页面不再提供 20 字节兼容模式。用户真机已反馈此模式升级正常，20 字节模式不可用。MTU 包含协议开销，不能直接当作写入长度。
- MTU 按平台处理：Android 请求 512 并读取实际结果；iOS 跳过 `setBLEMTU` 和 Android 专属变化监听，MTU 由系统管理；未知平台同样采用只读策略。adapter 优先通过 `getDeviceInfo().platform` 识别，旧运行时回退 `getSystemInfoSync().platform`。
- 主通道发现及通知启用后读取 MTU，Apollo 独立通道就绪后还会用 `writeNoResponse` 再读取一次。iOS 日志显示“已跳过手动设置”属于正常行为，不再打印不支持设置的协商失败。如果此时 MTU 仍为 23、读取不到或低于 240，升级会明确阻止；不会把返回值强制改成 240/512，也不会恢复 20 字节模式。
- “开始升级”按钮灰色时，页面会显示具体原因：文件未就绪、设备未连接或任务处理中。未连接可直接点击“连接 / 选择设备”，连接后返回会保留已选文件；无需退出升级页重新选择。MTU 检查在点击之后执行，不参与按钮置灰判定。日志以 `Apollo 开始条件` 为前缀记录所有判定状态，便于区分文件选择后的断连或读取未完成。

MTU 是当前手机与戒指连接双方支持能力共同决定的参数，微信从手机平台读取这条连接的结果，不是读取某个 bin 文件里的配置。iOS 端由系统处理协商，固件端仍需正确配置蓝牙协议栈的接收能力；最终 ATT_MTU 受双方支持上限约束。若要写入 237 字节，双方至少需支持 240 字节 ATT_MTU。仅凭小程序读取到 23 尚不能确定问题必在固件端，需要结合连接后的读取及固件侧 MTU 交换记录定位。

- 升级页依次显示文件头、正文、校验、重启确认。正文 100% 不等于升级成功；协议完成后点击“重连并读取固件版本”，查看实际版本（仅用于展示）。
- “停止升级”、离开升级页或应用退到后台会取消后续升级。打开前台日志页不取消；聊天选择器在文件准备阶段不会触发 OTA。
- 升级期间其他页面不能扫描、换设备、发起普通指令或手动断连；停止后请按固件恢复策略处理，不能把取消视为回滚或断点续传。
- 统一日志页显示网络请求、下载状态、完整逻辑包发送 Hex、原始 ACK、阶段和失败原因。带签名的 URL 参数和敏感 Header/Body 字段会脱敏。
- 完整分片与上下文另写入小程序用户目录 `apollo-ota-<时间戳>.log`，当前路径显示在升级页。升级结束后在日志页点击“复制完整 OTA 诊断日志”；该文件保留日志页滚动窗口之外的记录，复制失败时可用开发者工具提取。文件写入失败会明确提示只保留滚动窗口。

当前已完成模拟平台测试和 SDK bundle 构建；用户已反馈 MTU 至少 240 的模式真机升级成功，但未记录手机系统、来源和完整恢复测试，不能据此认定所有验收项完成。后续需分别验证 iOS/Android 下两种来源、237 字节分片、重启 ACK/断连时序、后台取消、失败恢复，以及重连后的版本。不要在无法恢复的正式设备上进行首次联调。

## 常见问题

如果页面没有显示功能按钮，通常是小程序页面脚本加载失败。当前 Demo 不需要执行“构建 npm”，请直接重新编译项目。

如果点击后提示“本地SDK文件加载失败”，请确认 `libs/bcl-ring-sdk.js` 存在。

如果微信开发者工具提示 `Cannot read properties of undefined (reading 'getDevCodeByFileList')`，这是开发者工具内部 npm/TS 编译链路错误。当前 Demo 已改为本地 SDK 文件，不需要执行“构建 npm”；请关闭项目后重新打开，并直接点击“编译”。

如果真机调试提示 `onPageNotFound error: page "" is not found`，说明微信开发者工具使用了空启动页。当前工程已在 `app.json` 和项目配置里显式设置首页为 `pages/index/index`。请在开发者工具顶部的编译模式中选择“首页”，或删除旧的编译模式后重新编译。

如果点击“蓝牙设备搜索”后提示扫描失败，请优先看弹窗里的具体错误码：

- `SDK包未加载`：需要执行“工具 -> 构建 npm”，再重新编译。
- `[10000] not init`：蓝牙模块未初始化，通常需要重新编译或重新进入页面。
- `[10001] not available`：手机蓝牙未开启，或当前环境不可用。
- `[10009] system not support`：当前系统或基础库不支持 BLE。
- Android 真机如果扫描不到设备，请确认系统定位权限和定位开关已打开。

蓝牙扫描建议使用真机调试。开发者工具模拟器通常不能完整验证 BLE 扫描和连接。


默认协议通道：

- Service: `0x0001`
- Write Characteristic: `0x0010`
- Notify Characteristic: `0x0011`

## Nordic 固件升级

首页「Nordic ZIP 固件升级」进入独立页面。先连接目标戒指，选择微信聊天中的 application ZIP，校验后点击「开始升级」。Demo 自动识别标准03/04入口、处理模式切换和升级连接，无需手动选择Bootloader；传输后自动恢复原设备的普通SDK会话并读取实际版本。失败时可只重连，不必重复刷写。

- 升级连接读取真实MTU，iOS只读不设置、Android请求后读回；MTU247使用244字节分片，无逐片10ms固定等待，保留Flash准备和CRC确认。
- 文件选择/校验期间不被后台事件误取消；实际BLE升级进入后台仍停止。日志保留停止来源、完整分片Hex和吞吐统计。
- 设备列表合并匹配戒指服务的系统已连接结果并标注来源，不等于枚举所有已配对设备。


## PHY 固件升级与 Boot 恢复

首页新增“PHY HEX 固件升级 / 恢复”，设备列表标记“PHY 恢复模式”的 PPLUSOTA 候选也可直接进入恢复页。正常升级先连接戒指；已经在 Boot 的戒指无需普通业务连接。聊天选择 HEX16/HEX、确认固件适配后开始，切换前保存持久固件及恢复记录。小程序重开后可加载原固件并重新搜索恢复。

协议完成后按原 MAC 新鲜扫描应用态并读回版本；“重新搜索并读取版本”只核验、不重复刷写。实际 MTU 需至少 240；失败从首分区重刷，不自动退出 Boot。
